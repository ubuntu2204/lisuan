# 豆包客户端版本约定

## 原则：只认官方最新版，不做旧版回退

**豆包 Windows 客户端在 Wine 下的目标是运行官方最新版（安装器渠道当前 `2.32.6` / Chromium `147.0.7727.149`；
客户端自更新后可更高，2026-11-08 实测运行中为 `2.35.8`）。
不得把「降级到旧版 `1.56.6`」当作解决方案、回退方案或验收通过的依据。**

禁止清单：

- ❌ 在修复脚本里检测到新版版本号就自动换回旧版目录（`fix-doubao-wine.sh` 中
  `current_version == 2.32.6` → 恢复 `1.56.6` 的回退分支）；
- ❌ 通过 patch `update.exe` 入口、`vulcan_update_block_versions` 屏蔽版本号等方式锁版本，
  把客户端钉死在旧版；
- ❌ 把「旧版能打开窗口」写成「已修复」或当作目标达成；
- ❌ 用旧版目录、`Program Files/Doubao/app` 的 1.56.6 作为新版方案的验收参照。

允许清单：

- ✅ 保留旧版文件不动，仅作为**历史对照**，用于对比崩溃点差异；
- ✅ 在旧版上做只读诊断（看日志、比对行为），但结论必须指向新版。

## 现状基线（2026-11-07 实测）

| 客户端 | 版本 | 状态 |
|---|---|---|
| `AppData/Local/Doubao/Application/app` | 2.32.6 / Chromium 147（安装器渠道；客户端自更新后可为 2.35.8） | **目标版本**。2026-11-08 起经 **Steam Runtime 容器** 启动，主窗口已映射并显示真实界面（546 色），主进程稳定；长时/登录/连续启动验收仍待完成 |
| `Program Files/Doubao/app` | 1.56.6 / Chromium 129 | 早期在 Deepin Wine 8.16 + Mesa 软件渲染下可出主窗口，**仅作历史对照** |

- 旧版 1.56.6 在 Deepin Wine 8.16 下确实能显示主窗口（`doubao.com/chat/` 正常渲染）。
  这说明前缀、WinSxS 链接、`LocalLow` 目录这些**前缀层修复是有效的**，
  与版本无关，新版可以继续复用。
- 新版 2.32.6 的第一个硬门槛：定制 Chromium 调用
  `GetProcAddress(ntdll, "RtlGetDeviceFamilyInfoEnum")` 后 `PCHECK` 失败，
  报 `FATAL:base\win\win_util.cc ... 找不到过程 (0x7F)`。
  Deepin Wine 8.16 **不导出**该函数；Proton 11.0（Wine 11）**有导出**，
  新版在该运行时下已越过这道门槛（仅剩 stub 日志，不再 FATAL）。
- 新版失败点与旧版成功点分离得很干净：**前缀环境已通，缺的是 Wine 版本级 API**。
  因此后续工作是补 Wine 运行时与渲染，不是继续修前缀。
- 2026-11-08 已闭环，但**要按图形会话区分**：旧会话（11-07 22:00 – 11-08 02:53）
  里裸跑宿主 wine 的主窗口一直 `IsUnMapped`（强制 XMap 也纯黑），
  `SteamLinuxRuntime_sniper` 容器是唯一成功路径（窗口 `IsViewable`、546 色、
  `chrome://doubao-chat/`）；机器 07:50:20 重启后，裸 wine 与容器**都能**出界面，
  换成全新空 `User Data` 亦如此。所以容器是**稳健默认而非唯一必要条件**，
  黑屏指向宿主图形会话状态（具体项未定论），容器靠隔离 Mesa/GL 栈绕开污染。
- 已排除：profile 状态、`Remote_State` 云配置、8 组渲染开关、网络（WinINet HTTPS 200）；
  给 Wine 8.16 补 `RtlGetDeviceFamilyInfoEnum` 导出只消除 8.16 的 FATAL，
  仍进修复流程且无主窗口，此路已证伪，不要重做。

## 官方最新版如何确认（2026-11-08 更新）

安装器文件名里那串数字**不是客户端版本**，三个不同名的安装器 SHA-256 完全相同
（`865d6bf9…43cf23e9`）。要确认“新版”到底是哪个，直接问官方接口，不用跑 Wine：

```bash
curl -s 'https://www.doubao.com/service/settings/v3/?device_platform=pc&brand=doubao&aid=582478&os=windows&update_type=downloader&version_code=2.25.16&os_version=10.0.22000' \
  | grep -oE 'doubao_pc/[0-9.]+/Doubao_win_X64_[0-9.]+-signed\.zip'
```

2026-11-07 与 2026-11-08 两次实测均返回 `2.32.6`，即**安装器渠道当前仍是 2.32.6**。

> ⚠️ **这个接口只代表安装器渠道，不代表客户端运行版本**（2026-11-08 新增，别再混用）。
> 客户端自更新后可以更高：同日 crashpad 记录里客户端自报
> `app_version: 2.35.8`，`channel: webdaoliu_doudi_online_installer_win`。
> 因此跑一次官方安装器会把客户端从 2.35.8 **落回** 2.32.6（实测：安装前 2.35.8 →
> 安装后 2.32.6），之后客户端自己的更新器再决定最终版本。
> 判断本机实际版本看 `Application/app/manifest.json` 的 `version` 字段，
> 运行期看 crashpad 的 `app_version`；**不得**用接口返回值直接断言本机版本。

安装入口固定为 `doubao/install-doubao.sh`。四个不得重犯的认知错误：

1. **`/S` 不是静默安装**。日志会记 `CmdLine:/S` 但紧跟
   `saman command line install mode is `（空），然后弹出 GUI 停在「立即安装」上空等点击。
   不得再把 `/S` 写成可用静默安装，也不得用 `/S` 跑完就判定安装失败。
2. **完成判据是安装日志的 `_OnInstallSuccess`，不是版本号变化**。
   同版本完整重装时版本号不变，拿“版本号变了没”当判据会误判为超时失败。
3. **自动点「立即安装」必须等窗口真正映射**。安装器窗口刚建出来时
   `map_state != IsViewable`，此时 `XGetImage` 抛 `Xlib.error.BadMatch`；
   要轮询 `map_state` 并重试抓图，不能一次抓不到就放弃。
4. **点击要走 XTEST 真实指针事件**（`mousemove --window` + `xdotool click`）；
   `xdotool click --window` 发的是 `XSendEvent` 合成事件，Wine 侧会忽略。

安装器属于厂商专有二进制，已进 `.gitignore`（`doubao/doubao_client_*.exe`），不入库。

## 已落地的代码清理（2026-11-07）

`doubao/fix-doubao-wine.sh` 中的违规逻辑已删除：

- ❌ 删除 `current_version == 2.32.6` → 从 `files.7z` 恢复 1.56.6 的回退分支；
- ❌ 删除 patch `update.exe` 入口（`xor eax,eax; ret`）的逻辑；
- ❌ 删除向 `saman_update_info` 写入 `vulcan_update_block_versions` 的屏蔽逻辑。

脚本现在只做与版本无关的前缀层修复（WinSxS 悬空软链接 → 前缀内相对链接、
补齐 `AppData/LocalLow`），并只读探测版本用于报告。
前缀可用 `DOUBAO_WINE_PREFIX` 覆盖，Windows 用户名按前缀实际内容解析
（Wine 11 前缀是 `steamuser`，不能假设是 `ubuntu`）。

## 推进路线

1. **主线：Wine 11 / Proton 11 前缀跑通 2.32.6。**
   新前缀独立于 `~/.deepinwine/doubao-wine`，不污染旧版对照路径。
   环境变量必须照 Proton `proton` 脚本：`WINEDLLPATH=files/lib/vkd3d:files/lib/wine`，
   `LD_LIBRARY_PATH` 含 `files/lib/x86_64-linux-gnu`、`files/lib/i386-linux-gnu`；
   前缀不能建在 `/tmp`；Windows 用户名先 `find` 确认，不要假设是 `ubuntu`。
2. **先解 API 兼容，再解渲染。** Wine API 兼容与 GPU 渲染是两个独立问题，
   不要混在一起排查，也不要用「换渲染后端」掩盖 API 缺失。
3. **`fix-doubao-wine.sh` 已清理为纯前缀层修复**，可在任意前缀运行：
   `DOUBAO_WINE_PREFIX=~/.deepinwine/doubao-wine11 ./doubao/fix-doubao-wine.sh`。
   但**不要**再往里加回退、锁版本或更新器禁用逻辑。
4. **主线启动器是 `doubao/run-doubao-wine11.sh`**（Steam Runtime 容器 + Wine 11 + 官方 2.32.6），
   安装/升级走 `doubao/install-doubao.sh`。
   `run-doubao-wine.sh`（旧入口）已改为**安全转发**到 Wine 11 启动器，
   不再启动 1.56.6 / Wine 8.16；残留旧快捷方式也不会再触发异常修复弹窗。
   1.56.6 历史对照改为直接用 `deepin-wine8-stable` 手动启动旧前缀，不得作为默认入口。
   桌面入口 `~/Desktop/doubao-wine.desktop` 已指向新版启动器并标记 trusted；
   若 Steam 更新替换了 `sniper_platform_*` 导致容器启动器缺失，启动器会明确报错，
   此时应修容器路径，**不得**把默认入口改回旧版或退回裸 wine 黑屏路径。
5. **硬件渲染目标是 7G100 的 gf。** 软件渲染（Mesa/llvmpipe）只作为定位
   API 兼容问题的诊断手段，不是最终验收标准；gf 加速要单独一轮评估，
   不要在 API 尚未打通时叠加硬件加速变量。

## 验收标准（新版 2.32.6）

- 60 秒内出现主窗口，且渲染的是豆包真实界面（不是白屏 / 崩溃页）；
- `CrBrowserMain` 连续存活 10 分钟以上；
- 没有新的 browser 主进程 Crashpad 转储；
- 登录、文字对话可用；
- 连续 3 次手动启动均正常；
- 版本跟随官方（安装器渠道或客户端自更新，以 `manifest.json` / crashpad `app_version` 实测为准），
  **不需要**禁用更新器或屏蔽版本号才能运行。

## 证据与日志

- 首次启动带 `--enable-logging=stderr`，日志单独落盘，不与旧版日志混写。
- 崩溃现场保留：不清理 Crashpad 转储、不做崩溃后自动重启
  （见 `崩溃处理约定.md`）。
- 前缀层修复（WinSxS 相对软链接、`AppData/LocalLow` 目录）对新旧版都有效，
  可作为独立工具保留，但不得再包含版本回退分支。
- 旧 Deepin 前缀的 `running_exception` 是排查期间强杀累积的，触发
  「当前版本启动发生异常」修复弹窗时，只允许**备份后清零该计数 + 修正入口**；
  不得禁用修复器、改名 `update.exe`、屏蔽版本号或删除账号数据来压制提示。
