# 崩溃处理约定

## 原则：不得用自动恢复掩盖故障

**任何游戏、应用、服务、脚本崩溃后，不得设置看门狗、自动重启、守护式拉起、
重试循环或常驻后台兜底来掩盖问题。适用于本仓库及所有项目，不限于游戏。**

禁止清单（包括但不限于）：

- 崩溃自动拉起、智能重试、失败后 `sleep` 再启动；
- supervisor / monit / watchdog / 进程存活监控后重新拉起；
- `systemd` 的 `Restart=always` / `Restart=on-failure` / `RestartSec` 兜底单元；
- 为「让故障不明显」而做的守护进程化、开机自启兜底、静默吞掉退出码或错误日志；
- 以减少报障频率为目的的任何「自动恢复」包装。

### 理由

自动重启会**掩盖问题**：

- 崩溃变得不可见 —— 用户只感觉到「闪一下」或「卡了一下」，难以察觉与复现；
- 掩盖崩溃频率与规律，给根因定位制造障碍；
- 可能引发「关不掉」的困扰：正常退出若被误判为崩溃，程序会被重新拉起。

宁可让程序直接退出，让崩溃**显式可见**，再据此定位根因。

### 正确做法

1. 先取证定位根因 —— 日志、core dump、`dmesg` / `journalctl`、apport、gdb；保留现场，不清理证据。
2. 修复根因。
3. 根因短期内无法修复时，**把选项交给用户并先取得明确同意**，再由用户决定是否接受
   「崩溃后重开 / 看门狗 / 守护」这类兜底；默认一律不做自动恢复。
4. 可以采用**用户主动执行的一次性启动**或**用户可感知、可控制的替代方案**
   （例如换用不依赖故障组件的另一个程序），但必须如实记录「原崩溃尚未修复」、
   保留根因证据，不得把「绕开」包装成「已修复」，也不得因此引入自动拉起。
5. 启动 / 替代脚本不得检测存活并自动拉起、不得设开机自启或守护；重复调用只打印状态。

### 允许与禁止的边界

- ✅ 允许：为修复根因而做的开机配置（如 `Type=oneshot` 的设备绑定服务）、
  应用本身的前台或一次性启动（即使 `nohup` 后台，只要没有存活监控 / 重启）、
  单次冒烟测试（结束后显式收尾）。
- ❌ 禁止：任何「监控 + 自动恢复」逻辑，无论用 systemd、shell 循环还是外部工具实现。

**不得**为了减少用户报障的频率，擅自加入自动重启。

### 与现有脚本的冲突（重要）

`underlords/fix-underlords-native.sh` **默认开启**自动重启，
用于兜底 Source 2 `libpanorama_text_pango.so` 的随机段错误
（该崩溃与显卡无关，属游戏自身问题）。

按本约定，应保持**关闭**状态：

```bash
# 确认当前状态
./underlords/fix-underlords-native.sh --status
# 期望显示：「自动重启已关闭」

# 若发现被开启，关闭它
sudo ./underlords/fix-underlords-native.sh --no-autorestart
```

⚠️ **不要**因为「游戏会闪退」就重新开启自动重启 —— 用户已明确表示
宁可闪退也不要自动重启。此时应转而定位根因。

### 排查霸业崩溃时的取证手段

崩溃不重启才留得下证据，配套手段：

```bash
# 让 core 落到 /tmp（默认 core_pattern 指向 apport，而 apport 目录常为空）
echo '/tmp/core.%e.%p' | sudo tee /proc/sys/kernel/core_pattern
ulimit -c unlimited
```

游戏已带 `-nobreakpad` 参数（游戏自带 breakpad 会吞掉 SIGSEGV，
关掉后崩溃才会产生内核 core）。相关日志：
`game/dac/console.log`（注意该文件可能不随每次运行更新）。
