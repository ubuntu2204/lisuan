# 命令超时约定

> 适用：本机全部排障/验证命令，尤其是 Wine/Proton 前缀、GUI 安装器、D-Bus 与
> 抓图会话。2026-11-19 固化：连续三次出现 `wineserver -w`、注册表操作、
> GUI 程序启动后命令不返回、用户手动取消，根因都是缺少超时。

## 一、总原则

1. **任何可能不自行退出的命令都必须显式超时**，不许依赖工具默认超时，
   也不许在注释里写“应该很快结束”。
2. 超时不是修复手段，只是防挂死的护栏：超时后按原样记录退出码 `124`，
   先清理残留进程/会话再继续，不得把“超时”当成“成功”。
3. 禁止无超时的 `wineserver -k` / `wineserver -w`、`wine reg ...`、
   `wineboot`、`wine <gui.exe>`、`python3 capture-wayland-screen.py`、
   `ssh` 到 Windows 试验机、长任务 `sshpass` 会话。

## 二、按场景的超时模板

```bash
# Wine 前缀维护：所有命令都带 timeout，退出码原样保留
timeout 20 env WINEPREFIX="$P" "$WINE" wineserver -w || rc=$?    # 24 释放；124=挂死
timeout 20 env WINEPREFIX="$P" "$WINE" reg delete 'HKCU\Software\Wine\X11Driver' /v UseShape /f
timeout 30 env WINEPREFIX="$P" "$WINE" wineboot -u

# GUI 安装器/应用：短探测用 60-120s，完整安装/单应用运行用 300-900s
timeout 900 env ... "$WINE" "$INSTALLER" /S
timeout 15 timeout 60 "$WINE" notepad          # 短窗口探测；防 GUI 不退

# 计划任务 / SSH 远程 Windows：必须外层 timeout，且结束兜底清理
timeout 45 sshpass -p "$pwd" ssh user@host 'cmd /c ...'
timeout 45 sshpass -p "$pwd" ssh user@host 'taskkill /IM xxx.exe /F 2>nul' || true

# 任何自写 Python 排障脚本：脚本内建 --timeout，默认不超过 25s
python3 .codebuddy/skills/lisuan-7g100-compat/scripts/capture-wayland-screen.py --timeout 20 -o /tmp/shot.png
```

## 三、超时后的清理顺序

1. 只按本次进程树精确清理：先 `pgrep -af <exe 名>` 核对，再 `pkill -f <完整启动命令>`；
   `wineserver -k` 必须也带 `timeout`，不可裸跑。
2. 检查 ScreenCast 会话已 Stop（`capture-wayland-screen.py` 由 `finally` 保证），
   不留后台录屏。
3. 清理后重跑只读体检（`--status` / `--check`）确认状态，不直接重试安装/启动。

## 四、坑位记录（2026-11-19）

- Windows 对战平台安装器 `/S` 返回 0 但不落盘；交互方式启动反而静默安装成功。
  这类“返回 0 但无产物”的 GUI 安装器必须同时校验主程序 PE 头，
  并且所有探测运行都要带 `timeout`，否则窗口不退出会挂死会话。
- `wineserver -w` 在 prefix 有残留服务时会一直等；`reg delete` 后跟裸
  `wineserver -w` 是本次两次“卡住”的直接触发点。
- 双屏扩展环境（X11 root 3840x1080，HDMI-1 左 + DP-1 右）下，
  `capture-wayland-screen.py` 默认 connector 取到 DP-1，容易抓到空桌面；
  必须显式 `--connector HDMI-1` 或按 `xrandr --listmonitors` 指定。
  2026-11-19 晚本机已改为双屏镜像（两输出都 1920x1080+0+0），
  两屏内容相同、看任一屏即可；若改回扩展模式，恢复显式指定 connector。
